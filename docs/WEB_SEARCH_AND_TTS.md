# 联网搜索与第三方 TTS

这两项功能都是**可选**的，默认关闭。原生播放已经可用时，不配置它们也能正常工作。

## 🔍 联网搜索（Tavily）

开启后，每轮对话的流程是：

```text
用户问题
→ 模型判断是否需要联网，并生成搜索词（返回 JSON）
→ 需要时调用 Tavily
→ 把标题/摘要/来源作为「不可信资料」注入这一次请求
→ 模型基于资料回答 → 音箱播报
```

搜索摘要只用于当次回答，不会作为历史长期保存，避免污染后续对话。

### 配置

控制台 → **AI 服务** → **联网搜索**：

| 字段 | 说明 |
|---|---|
| 启用联网搜索 | 总开关，默认关闭 |
| Tavily API Key | 在 https://app.tavily.com 申请 |
| 每次最多来源 | 建议 3～5，条数越多回答越慢 |
| 搜索缓存（秒） | 相同问题在此时间内不会重复消耗额度 |

额度参考：Tavily 免费档每月 1,000 credits，`basic` 搜索每次 1 credit，即约每月 1,000 次实际搜索。模型判断本身不消耗 Tavily 额度，但会多一次模型请求。

### 安全边界

- 搜索端点只允许 `https://api.tavily.com`，可在代码层拒绝其他主机。
- 结果中的链接只接受 `https`，并过滤本机与回环地址，避免 SSRF。
- 摘要与标题有长度上限，响应体也有大小上限。
- 结果按「不可信资料」注入，并明确要求模型不要执行其中的指令。

## 🔊 第三方 TTS（火山引擎）

### 先说清楚它能做什么、不能做什么

- **能**：换音色，让播报不是小爱默认声音。
- **不能**：解决「小爱先用自己的回答播一遍」。这是走 API 方案的固有限制，`abortXiaoAI` 在 MiGPT-Next 中是空实现，不刷机无法打断小爱自己的回复。

如果只是想让音箱出声，优先用原生播报；需要换音色再配这个。

### 新版控制台（推荐）

1. 打开 https://console.volcengine.com/speech/service/9999
2. 开通「语音合成大模型」
3. 复制两个值：
   - **API Key**
   - **音色 ID**（形如 `BV001`）
4. 控制台 → **语音合成** → 选择「火山引擎（豆包）」：
   - 填入 API Key
   - 填入音色 ID
   - 填入**对外地址**（见下）

请求鉴权使用 `x-api-key` 头。

### 旧版控制台（兼容）

若账号仍是旧版，使用 `App ID` + `Access Token`，鉴权走 `Authorization: Bearer; <token>`。控制台里已折叠在「旧版控制台」区域。

### 对外地址必须填

第三方 TTS 的原理是让**音箱去拉一个音频 URL**，所以：

- 必须填写 `publicURL`，且是音箱能访问到的地址；
- 如果服务跑在电脑上，要填电脑的局域网 IP，例如 `http://<你的电脑局域网IP>:36592`；
- 填 `127.0.0.1` 音箱是访问不到的。

### Cluster

默认 `volcano_tts`，一般不用改。如果火山侧提示音色或集群不匹配，可以在这里调整。

## ⏱️ 关于「小爱先自己答一遍」

这是走 API 方案的固有限制，**没有刷机就无法彻底解决**。原因有两层：

1. `abortXiaoAI()` 在 MiGPT-Next 中是空实现，返回 `false`，不会中断小爱。
2. 更关键的是消息获取方式：上游只在设备**已经产生回答之后**，才能在会话记录里读到这条用户消息（过滤条件要求该记录的 `answers[0].type` 是 `TTS` 或 `LLM`）。等我们拿到消息时，小爱通常已经开口。

本项目做的缓解是：命中唤醒词后**立刻**暂停设备播放，然后才去调用模型。

```text
收到消息
→ 停止当前播放 + MiNA.pause()    ← 尽早截断
→ 判断是否需要联网 → 搜索 → 生成回答
→ 再次 pause() 并注入播报
```

这会缩短小爱声音和模型回答的重叠，但**不能阻止小爱先开口**。

想彻底打断只有刷机走 Open-XiaoAI 路线。

## 🎙️ 音箱播放命令


不同机型的 MIoT 指令不同，本项目默认按 **L05C / 小爱音箱 Play 增强版** 配置：

| 用途 | 指令 |
|---|---|
| 唤醒 | `5,1` |
| 播报文本 | `5,3` |
| 停止播放 | `3,4` |

参考官方 MIoT 规格：`urn:miot-spec-v2:device:speaker:0000A015:xiaomi-l05c:1`，其中服务 5 是智能音箱（动作 1 唤醒、动作 3 播放文本），服务 3 是播放控制（动作 4 停止）。

其他机型请查阅 https://home.miot-spec.com ，并在控制台的「语音合成」页填写。

## 🧪 排障

**搜索没触发**

看日志是否有 `联网判断`。若显示 `fallback`，说明模型没返回可解析结果，此时会按关键词规则决定是否搜索。

**搜索触发了但回答没用到资料**

看 `Tavily 搜索完成：N 条结果`。若为 0 条，通常是搜索词太窄或额度用尽。

**音箱不出声**

日志应为：

```text
TTS 退出聆听：暂停=true
TTS MiOT 5,3：true（N 字）
```

若出现 `MiNA 回退：成功`，说明 MiOT 播放文本这条路没被确认，实际是否出声要听设备。

**第三方 TTS 没声音**

优先检查 `publicURL` 是否为音箱可达的局域网地址。
